# Fix summary: cake-pan-converter

Lead engineer: Tony. Findings from 6 review files (maintainer, minimalism, readability, regression, customers, design and SEO) were checked against the code.

## Fixed (accepted)
Must items
- Unit toggle drift (5 reviewers): state now stays in inches at full precision. Boxes are written from state and read only when typed in. 8" stays 8" after any number of toggles. Test added.
- Shared link crash (`constructor`, `__proto__`): `Object.hasOwn` in `dec` and `panProblem`. Test added.
- Ingredient parser: all amounts on a line are scaled (plus, `+`, `(2 sticks)`, `/240ml`, ranges); bare count plus bracket (`2 (8 ounce) packages`) no longer scales twice; cans and packages stay whole with a note; `1-1/2` is one number; step numbers (`1. 2 cups`) are skipped; `350 degrees F`, `12 servings` stay as they are; a line with an amount in the middle is scaled and flagged "Check this line". Tests added for each.
- Oven unit split from the size unit: own °F/°C buttons, link keeps it (`tu=c`).
- Size boxes: `8 1/2`, `9,5`, `8½` parse; junk gives a named message. `Infinity`, `NaN`, 400 inches, 0 or 30 pans are rejected with a message that names the field. Stale factor now shows a dash.
- Tiny amounts never print 0 (`1/8 tsp` x 0.5 gives "a pinch of"); egg and cup and stick plurals follow the printed amount; yolks and whites round to whole numbers; egg note is clearer.
- Phone layout: a bottom bar with the factor, "See result" and "Copy" shows while the answer is off screen.
- Sheet pan answer: sheet fill depth default is 2 (same as a cake pan), so 9x13 to half sheet is 2.00x. A line under the result appears when depths differ. Article explains it.
- README rewritten for this tool.
Should and nice items
- Bundt guide: one rule, no opposite lines. 70% text removed (the range already says it; FAQ matches). Same-depth range narrowed to about plus or minus 5%.
- Names: loaf is "9 x 5" everywhere (presets, drawing, copy); count is "(2 pans)" so it cannot read as a size.
- Drawing shows up to 3 stacked pans, larger labels, text alternative with both pan names.
- Link loads on `hashchange` (pasted link, back button). cm links store cm (20, not 7.874). One preset tolerance (0.01). Same default preset index in both units. Notice when the list is cut at 1500 characters.
- Logic moved out of the DOM script into `calc.js` (`describeScale`, `areaText`, `volumeText`, `bundtRadius`, `parseSize`, unit constants) and tested. `bundtRadius` written once with a comment. Shared `mk`, `el<T>`, `link()`. `unitGap` rewritten. Bundt cup presets defined once. Constants named (`UNICODE_FRACTIONS`, `FRACTIONS_CUP`).
- A11y: `aria-live` only on the sentence; Swap button label fixed (Lighthouse label-in-name); tap targets 44 px (header, footer, unit buttons); noscript message; "Try an example"; "Scaled for your pan" heading; "Pan capacity" instead of "Volume"; Area shows n/a for bundt; taller ingredient box.
- SEO: meta keywords removed; hero text and meta description rewritten (meta: "8 inch to 9 inch round is 1.27x..."); Article now says volume; JSON-LD has `image` and `featureList`; no canonical on 404.
- Privacy: no upload claim; consent wording matches reality (Google's consent message when ads are on); US spelling; "Last updated" fixed at October 20, 2026 (in `site.config.ts`). ThemeToggle "color".

Template items (all done)
- README for this tool. US spelling checked (grep clean). Fixed date on Privacy and Terms. No absolute paths in scripts. `scripts/new-tool.sh` removed. `screenshots/` untracked and ignored; `.playwright-cli/` ignored (it was never tracked). Duplicate link row removed from the home page (header and footer keep the links). `deploy` runs `npm test` first.
- CSS size: 22.3 KB before, 23.7 KB after (under 30 KB, so no Tailwind scan limit needed).

GitHub Pages
- `astro.config.mjs` reads `PAGES_BASE` (default `/`) and `PAGES_SITE` (default the real domain). All links, icons, manifest (now generated by `src/pages/site.webmanifest.ts`) and og:image use `url()` from `src/lib/paths.ts`. Canonical and og:url always point to cakepanconverter.com. og:image uses the serving address so it loads on github.io.

## Rejected or not done, with reasons
- Move the 270-line UI script to `ui.ts` and split `update()` (maintainer, readability): not done. It is one tool, the logic is now tested in `calc.js`, and a split would add files with no user gain.
- `calc.d.ts` or converting `calc.js` to TypeScript (maintainer, minimalism): not done, would add build steps; `any` casts reduced instead.
- Weight toggle (cups to grams) and muffin option: rejected, makes the tool a bigger app.
- Fill check "more than two thirds full" (design row 12): not done; needs a batter volume input, which is a new feature. The fixed "no more than two thirds full" line stays.
- Result before the second form / sticky right column on desktop: not done; the phone bar covers the real problem and desktop shows the result after one scroll.
- Muted placeholder colors, CLS 0.02 `min-h` tweak, `favicon.ico`, new cake-shaped icon, `lastmod` in sitemap, print layout, dark `brand-ink` lift: skipped as low value (Lighthouse is 100 on all four).
- `BreadcrumbList` and linking article rows to sub pages: wait for Phase 2 pages.
- Two tool H2s before the article H2: kept; the tool is the main content.
- Reviewer 22 (stale `dist/`): rebuilt clean; `dist/` is ignored.
- Minimalism "empty frontmatter in Article.astro", `Header` brand from `site.name`: left as is, harmless.
